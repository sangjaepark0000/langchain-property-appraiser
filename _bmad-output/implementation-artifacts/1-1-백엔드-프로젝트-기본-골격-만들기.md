# Story 1.1: 백엔드 프로젝트 기본 골격 만들기

Status: ready-for-dev

## Story

As a 개발자,
I want FastAPI 기반 백엔드 프로젝트 구조를 만들고 싶다,
so that 이후 RAG 기능을 안정적인 구조 위에서 구현할 수 있다.

## Acceptance Criteria

1. Given 깨끗한 프로젝트 저장소가 있다, When 백엔드 작업공간을 초기화한다, Then `backend/pyproject.toml`, `backend/app/main.py`, 승인된 backend 폴더 구조가 존재한다, And FastAPI, LangChain, LangGraph와 호환되는 Python 버전이 문서화되어 있다.
2. Given 백엔드 의존성이 설치되어 있다, When FastAPI 앱을 로컬에서 실행한다, Then 기본 health endpoint가 성공적으로 응답한다, And LLM, embedding, LangSmith, database credentials 없이도 앱이 시작된다.
3. Given 새 개발자가 저장소를 연다, When setup 문서를 읽는다, Then backend 환경 생성, 의존성 설치, local API 실행 방법을 확인할 수 있다.

## Dev Notes

### Epic Context

Epic 1은 local-first 환경에서 FastAPI backend, PostgreSQL/pgvector, 설정, migration, 기본 프로젝트 구조를 갖춘 실행 가능한 RAG 개발 작업공간을 만드는 것이 목표다. Story 1.1은 이 epic의 첫 구현 story이며 후속 설정, DB, Alembic, source inventory, smoke command story의 기반이다. [Source: `_bmad-output/planning-artifacts/epics.md#Epic 1: Local RAG Development Workspace`]

### Architecture Guardrails

- Backend-first FastAPI가 선택된 starter approach다. 웹 UI보다 FastAPI backend와 CLI/API smoke test를 먼저 만든다. [Source: `_bmad-output/planning-artifacts/architecture.md#Selected Starter: Backend-first FastAPI, then SvelteKit`]
- Architecture 문서의 최신 확인 버전:
  - FastAPI `0.136.1`
  - Uvicorn `0.47.0`
  - LangChain `1.3.1`
  - LangGraph `1.2.0`
  [Source: `_bmad-output/planning-artifacts/architecture.md#Verified Current Package/CLI References`]
- Architecture는 구현 전 backend Python version 명시를 요구한다. 로컬 Python 3.14보다 Python 3.12 또는 3.13이 package compatibility 측면에서 더 안전할 수 있다고 기록되어 있다. [Source: `_bmad-output/planning-artifacts/architecture.md#Open Questions / Follow-Ups`]
- DB table/column, API JSON field, Python variable은 `snake_case`; Python class와 Pydantic schema class는 `PascalCase`를 사용한다. [Source: `_bmad-output/planning-artifacts/architecture.md#Naming Conventions`]
- Route handler는 얇게 유지하고 business logic은 `services/`, `rag/`, `graph/`로 분리한다. Story 1.1에서는 business logic을 만들지 말고 skeleton과 health만 구현한다. [Source: `_bmad-output/planning-artifacts/architecture.md#Backend Folder Rules`]

### Required Backend Structure

Story 1.1에서 최소 생성해야 하는 구조:

```text
backend/
  pyproject.toml
  app/
    main.py
    api/
    core/
    db/
    models/
    schemas/
    ingestion/
    rag/
    graph/
    services/
  tests/
```

Architecture의 complete structure에는 이후 story에서 `backend/alembic`, scripts, concrete model/schema files가 추가될 수 있으나 Story 1.1은 skeleton/health/docs에 집중한다. [Source: `_bmad-output/planning-artifacts/architecture.md#Project Structure & Boundaries`]

### Scope Boundaries

Do:
- Backend skeleton, dependency metadata, minimal FastAPI app, health endpoint, setup docs, simple tests.
- Keep startup independent from DB/provider credentials.

Do not:
- Implement `.env`/typed settings in depth; Story 1.2의 범위다.
- Add PostgreSQL/pgvector Docker Compose; Story 1.3의 범위다.
- Add SQLAlchemy/Alembic; Story 1.4의 범위다.
- Add source inventory/canonical schema docs; Story 1.5의 범위다.
- Add smoke command/logging framework beyond basic test/run docs; Story 1.6의 범위다.
- Add RAG, ingestion, retrieval, LangGraph runtime, or frontend implementation.

### Testing Requirements

Epic 1 test design requires fast local checks with no LLM, embedding, LangSmith, external API key, or DB. For Story 1.1, implement:
- Import test: `from app.main import app` succeeds.
- FastAPI TestClient health check returns HTTP 200 and expected payload.
- Static/file existence checks are acceptable for required skeleton directories.
[Source: `_bmad-output/implementation-artifacts/test-design-epic-1.md#Story 1.1 — 백엔드 프로젝트 기본 골격 만들기`]

### Expected Commands

Developer should ensure these or equivalent commands work from repository root or documented backend directory:

```bash
cd backend
python -m pip install -e .[dev]
pytest
uvicorn app.main:app --reload
```

If the selected packaging tool does not support `.[dev]`, document the exact supported install command and keep it simple.

### Existing Code Notes

At story creation time, no `backend/` application code exists in the repository. This story is expected to create new backend files rather than modify existing backend files.
